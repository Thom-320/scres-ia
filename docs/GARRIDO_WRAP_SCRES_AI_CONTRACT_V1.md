This contract is the durable scientific record for answering Garrido, Pongutá & Adarme
(2024) with the Garrido-Ríos (2017) WRAP thesis. It is deliberately separate from
`CLAUDE.md`, which describes repository-level agent objectives.

## 1. Questions and claim boundary

### Primary questions

1. Which AI family is empirically useful for representing supply-chain learning (SCL)
   on the WRAP decision design?
2. How can that family be placed between a DES run and the next SCRES decision so that
   information is retained between runs?

### Derived v.0 hypotheses

- **H1:** a learning-enabled run has lower system recovery time than a matched static
  comparator. `RPj` remains an order-attribution quantity and is not a system TTR.
- **H2:** performance or selection regret improves as the number of runs increases.
- **H3:** performance dispersion across predeclared risk intensities changes under
  learning. WRAP supplies no cost field, so cost volatility is not a WRAP claim.
- **H4:** a retained learner differs from a reset learner on new, matched disruptions.

“Predictive accuracy” means held-out prediction of WRAP `ReT` before executing the DES.
It does not mean anticipation, prevention, or better intra-episode control.

## 3. WRAP physical contract

The strict physical lane is `thesis_1to1`:

- 13 operations and the Chapter 6 risk distributions;
- 8,064 hours per thesis year and 161,280 hours total for the 20-year design;
- warm-up at the first 5,000-ration arrival at Op9;
- Table 6.16 inventory levels and Table 6.20 shift capacities;
- no RL reward, adaptive benchmark regime, post-warm-up priming, or normalized action
  multipliers;
- the published Cf1–Cf90 design, with common-seed pairing across buffer/shift contrasts
  where the thesis specifies it.

The repository's endogenous behavioral fidelity gate is currently not promoted. Until
that gate passes, the DES is a **thesis-grounded reconstructed DES**, not an exact
behavioral reproduction.

## 4. Metric contract

The workbook ReT formula is retained for continuity, but its `ΣBt` semantics remain an
explicit open item. The repository's capped backlog implementation is a disclosed proxy,
not an author-confirmed definition. Therefore:

- `ReT_workbook` is `PROVISIONAL` until the `ΣBt` question is closed;
- `fill_rate`, backorders, delivered flow, and service-loss metrics are always reported
  alongside it;
- `Re^min = 0` is treated as source-defined, so the DP/RP branch contributes zero by
  construction;
- no neural claim may rely on ReT alone while the metric gate is unresolved.

## 5. Q1 interface and decision rule

The invalid task is `drivers -> ReT`: the driver decomposition already contains the
response. The valid task is:

```text
(buffer_hours, shifts, risk_family, risk_pattern) -> held-out ReT
```

The comparison is constant, linear, backprop/MLP, and KAN. Features deliberately exclude
all observed drivers. Splits are grouped by the reused base seed/Cf triplet; random row
splits are forbidden.

A neural family is eligible for promotion only when its B1 held-out R² exceeds the linear
baseline by at least `SESOI_R2 = 0.05` and the paired 95% confidence interval for the
fold-wise difference excludes zero. B2 activation accuracy is secondary evidence.
If no model passes, the decision is `NO_GO_NEURAL_PREMIUM_IN_WRAP_PANEL`.
Regardless of model score, promotion remains blocked while the WRAP behavioral or metric
gate is `HOLD`.

## 6. Q2 between-run interface

Each simulation run has the following interface:

```text
input:  rho_k + known risk-design features
DES:    thesis-grounded WRAP simulation
output: ReT, drivers, fill/service/backlog metrics
state:  learner state theta_k only
next:   rho_(k+1)
```

The first closed-loop implementation compares:

- Garrido's deterministic OFAT order;
- a linear active selector;
- the Q1-selected neural selector, only if Q1 passes;
- retained versus reset state;
- shuffled campaign order and no-update controls.

The candidate pool, run budget, exogenous seed/tape and evaluation configurations are
identical across arms. The learner may retain observations/model parameters but may not
retain inventory, WIP, backlog, RNG state, future events, or a normalizer fit on test data.
PPO and intra-episode control are out of scope for this first Q2 answer.
